No country-specific exception or unsupported causal claim is introduced.

## Actual LCP and critical path

The five requested template probes below each have seven fresh-process A and seven B samples from the final full session. The LCP element is the existing paragraph `.direct-answer`, not the decorative hero or its title. Its computed font is Outfit,16px,300 in both arms (B adds the metric fallback alias). Paragraph content varies legitimately by destination/place and is protected from change; it does not demonstrate a Germany-only markup fault. These are route-specific paragraphs inside the same template, not separately styled exceptions.

Destination B inlines the existing two matching variable font families, avoids font network fetches and uses a plain reference navy hero. The shared selfhost method elsewhere uses seven exact static reference weights and two first-frame preloads. The existing common font gate waits for Outfit300 and Cormorant Garamond700, then the document font set, with a3s reveal failsafe. This makes font readiness a critical-path dependency; the LCP paragraph itself only needs Outfit300. That all-font-set wait is a plausible cost centre, not a measured uniquely German defect. Removing it without reliable CLS/LCP controls could reintroduce glyph swaps. No unvalidated gate change is made.

Hero stills are disabled/unreferenced. A gradient has no image request, so an alleged hero-image download cannot explain Germany. External blocking request differences and exact font URL/bytes, loaded font faces, paint-gate events and LCP nodes are in the A/B JSON. Passive DOM event times are real local navigation timestamps, not the Lighthouse simulated LCP clock; ordering is diagnostic only.
